# 2026-09-25 SEO 보강

변경 코드와 운영 검증 결과를 구분해 기록한다. 로컬 카탈로그는 70작품·100투어·181정거장이며 통합 빌드와 검사를 통과했다. 직전에 운영에서 확인한 목록은 70작품·80투어다. 새 빌드의 운영 배포와 Google 소유권 확인은 아직 완료로 기록하지 않는다.

## 정식 도메인

작업 시작 당시 [www.scene-trip.com](https://www.scene-trip.com)의 HTML canonical과 사이트맵 URL이 이전 `scene-korea-mauve.vercel.app`을 가리켰다. 사용자에게 보여주는 도메인과 검색용 주소가 달랐다.

Vercel의 Production·Preview·Development에 설정된 `NEXT_PUBLIC_SITE_URL`을 `https://www.scene-trip.com`으로 변경했다. HTTP 주소와 www 없는 주소가 정식 www 주소로 이동하는 것은 확인했다. 환경변수를 바꾼 뒤 생성하는 빌드의 canonical·OG 주소·사이트맵은 배포 후 다시 확인해야 한다.

`src/common/utils/site-url.ts`는 운영 기본값으로 정식 도메인을 사용한다. `next.config.ts`에는 기존 운영 Vercel 별칭을 정식 도메인으로 보내는 영구 이동 규칙을 추가했다. 검토용 배포는 검색 색인에서 제외한다.

## 작품과 투어를 연결하는 페이지

| 페이지 | 역할 |
| --- | --- |
| `/` | 전체 투어 탐색과 검색·필터 |
| `/filming-locations` | 작품별 탐색 목록. 작품 가이드가 있으면 가이드로, 없으면 개별 투어로 연결 |
| `/filming-locations/[slug]` | 별도 소개문과 장면·지역·이동 방법 비교가 있는 작품 가이드 |
| `/stories/[slug]` | 하루 이내의 개별 투어와 장면별 장소·방문 안내·지도 |

복수 코스를 가진 21개 작품 모두에 별도 소개문이 있는 가이드를 연결했다. 작품 가이드는 여러 코스를 하나의 연속 일정으로 합치지 않는다. 각 코스를 비교해 하루에 방문할 이야기를 고르도록 안내한다. 투어가 하나인 나머지 49작품은 작품 목록에서 투어로 바로 연결한다.

투어의 H1에는 작품명과 스토리 제목을 넣는다. 화면의 탐색 경로와 BreadcrumbList가 같은 작품·투어를 가리키도록 연결한다. 모든 공개 페이지를 사이트맵에서 읽는 검사는 코스 수를 고정하지 않는다.

이번에는 기존 작품의 다른 장소·장면으로 20투어·25정거장을 추가했다. 같은 작품의 기존 정거장과 새 장소의 이름·한글명·지도 검색어를 대조했고, 정거장별 장면 출처가 각 코스의 출처 목록과 연결되는지 확인했다. 조사 초안과 통합 데이터가 일치하며, 새 장소는 각 지역 안에서 45분–4시간의 방문으로 구성했다. 첫 장소까지 가는 광역 이동은 별도다. [추가 장면 조사 기록](research-2026-09-25-additional-scenes.md)에 출처별 확인 범위와 방문 제한을 남겼다.

## 메타데이터와 공개 안내

`getPageMetadata`가 고유 제목·설명, canonical, Open Graph와 Twitter 정보를 구성한다. About과 Privacy도 각각의 내용을 설명하는 검색 제목과 설명을 갖는다.

About에는 해외 팬 반응에서 작품을 찾고 한국 블로그·관광 자료·해외 방문기를 대조하는 조사 과정을 적었다. 자료 범위는 코스마다 다르며 모든 장소를 직접 방문하거나 모든 작품을 네 권역에서 조사했다는 주장은 하지 않는다.

Privacy에는 북마크의 localStorage와 탭별 목록 위치 복원의 sessionStorage를 구분했다. 폰트 파일은 사이트에서 제공하므로 이용자 브라우저가 Google Fonts로 파일을 요청한다는 이전 문구를 고쳤다.

구조화 데이터는 Organization, WebSite, CollectionPage, ItemList, BreadcrumbList, TouristTrip을 사용한다. 사이트맵의 수정일은 콘텐츠 날짜를 사용하며, 배포할 때마다 임의로 갱신하는 날짜와 구분한다. 구조화 데이터가 있다는 이유로 특정 검색 결과 형식이나 순위가 보장되지는 않는다.

## 브라우저로 보내는 데이터

기존 저장 기능은 코스 ID를 확인하기 위해 전체 촬영지 데이터를 가져왔다. 이 코드가 공통 메뉴에 연결되어 About과 Privacy에서도 전체 카탈로그 JavaScript가 필요했다. `SavedRoutesProvider`가 서버에서 ID 목록만 받아 이 의존을 제거한다.

카드 변환 함수는 화면에 필요한 필드만 선택한다. 검색 목록에는 서버에서 정리한 검색 텍스트를 더해 작품·장면·장소 검색을 유지한다. 사진과 전체 장면 설명은 투어 상세에서 계속 제공한다.

아래는 80투어 데이터에 `JSON.stringify`를 적용한 UTF-8 크기다. 네트워크 전송량이나 페이지 전체 성능 측정치는 아니다.

| 데이터 | 크기 |
| --- | ---: |
| 이전 전체 코스 데이터 | 225,427B |
| 검색 가능한 목록 데이터 | 95,066B |
| 저장·관련 카드 데이터 | 34,694B |
| 저장 기능의 ID 목록 | 1,963B |

검색 인덱스를 바꾼 뒤 기존 결과와 축약 데이터의 결과가 같은지 확인했다. 폰트는 CSS의 외부 `@import`에서 `next/font`로 옮겼다. 최종 카탈로그의 번들 크기와 운영 성능은 새 빌드에서 다시 측정해야 한다.

## 검증 명령과 현재 상태

빌드와 기본 검사는 `npm run build`, `npm run check`로 실행한다. 빌드한 서버가 3104 포트에서 실행 중이면 다음 명령으로 HTTP 응답을 검사한다.

```sh
npm run check:seo -- --base-url http://localhost:3104 --canonical-origin https://www.scene-trip.com
```

`scripts/check-seo.mjs`는 사이트맵의 페이지 URL만 읽으며 이미지 URL을 페이지 수에 포함하지 않는다. 동시에 보내는 요청은 최대 4개다.

- 공개 페이지의 200 응답과 고유 제목·설명을 검사한다.
- canonical과 OG URL의 도메인·경로를 대조하고 쿼리·해시가 섞였는지 검사한다.
- JSON-LD 문법, 탐색 경로의 URL·순서·부모 링크와 투어 정거장 수를 확인한다.
- 투어 H1의 작품명·스토리 제목과 사이트맵의 ISO 수정일 형식을 확인한다.
- 저장·요청 페이지의 noindex, 없는 투어의 404와 robots.txt의 사이트맵 주소를 확인한다.
- 소수의 이미지 URL에 HEAD 요청을 보내 존재 여부와 응답 형식을 확인한다.

100투어를 통합한 뒤 `npm run build`와 `npm run check`가 통과했다. HTTP SEO 검사는 공개 페이지 125개와 표본 이미지 4개의 응답, 보조 페이지의 noindex와 없는 투어의 404를 확인했다. 공개 페이지 수는 투어 100개·작품 가이드 21개·홈과 About·Privacy·작품 목록 4개를 합친 값이다.

브라우저에서는 모바일 상세·작품 가이드에 가로 넘침이 없고, 실제로 저장한 투어가 Saved에 나타나는 것을 확인했다. Goblin 필터를 적용한 목록에서 상세로 갔다가 브라우저 뒤로가기를 했을 때 검색어와 스크롤 위치 1,706px도 유지됐다. 운영 재배포 뒤의 HTTP 응답과 검색 서비스 확인 결과는 별도로 기록한다.

## 검색 서비스 등록

작업 시작 시 Google Search Console에 해당 속성이 없어 등록을 진행 중이다. 공개 확인 토큰을 Vercel Production의 `GOOGLE_SITE_VERIFICATION`에 설정했다. 배포 뒤 소유권 확인과 사이트맵 제출 결과를 확인해 이 문서에 기록한다. 사이트맵 제출과 실제 검색 색인은 서로 다른 결과다.

`GOOGLE_SITE_VERIFICATION`과 `BING_SITE_VERIFICATION`은 선택 환경변수다. 제공받은 HTML 메타 태그 전체가 아니라 `content` 값을 넣는다. Bing 등록 완료 여부는 아직 확인하지 않았다.
